# 79 次训练逐项拆解

> 这份文档回答一个问题：**"79 次"这个数字，每一部分是干什么的。**
> 目标：随便点一个数字，你都能说清它在问什么、为什么必须问、答案是什么。
> 视角：假设实验是队友跑的，你负责讲清楚——所以每一节都按「问什么 → 怎么做 → 答案 → 为什么只能这么答」写。

---

# 一、79 是怎么加出来的

79 不是"跑了 79 遍"，是**六类实验 + 一次正式训练**：

| 批次 | 次数 | 在回答什么问题 | 结果文件 | 支撑 PPT |
| --- | --- | --- | --- | --- |
| ① S1 单因子扫描 | 33 | 11 个超参数里，哪几个值得调？ | `runs.csv`（s1_01–s1_33） | P5 敏感性图 |
| ② 基准配置 | 1 | 给所有对比一个统一的参照点 | `runs.csv`（base） | 全部 |
| ③ S2 两两网格 | 4 | 两个最敏感的参数会不会互相影响？ | `grid.csv` | P5、P16 |
| ④ S3 三随机种子 | 9 | 那个提升是真实的还是运气？ | `repeats.csv` | P9、P10 |
| ⑤ 结构对照 | 6 | MLP 和 ViT 谁更强？ | `structure.csv` | P7 |
| ⑥ 容量对齐 | 18 | 参数量拉平之后，结论还成立吗？ | `capacity.csv` | P8 |
| ⑦ 对抗训练 | 6 | 模型被扰动打崩之后，能救回来吗？ | `adv_train.csv` | P14 |
| ⑧ 正式训练 | 2 | 产出最终权重 + 验证可复现性 | `outputs/best.pth` | P11 |
| **合计** | **33+1+4+9+6+18+6+2 = 79** | | | |

**注意两个口径**（被问到必须能答）：

- **79 不含压缩实验**（剪枝 3 次 + 从头训 1 次 + 蒸馏 3 次 = 7 次），也不含 FGSM 的 9 档评测（那是评测，不训练）。
- **79 里最后 2 次是同一个配置**：一次正式训练产出 `best.pth`，一次是为验证可复现性重跑，两次指标完全一致（0.988956）。这反而是个加分项——同配置同种子能逐位复现。

---

# 二、六类实验的关系：一条"逐层追问"的链

不要把它们当成六件并列的事，它们是一条链，每一环都是被上一环的缺陷逼出来的：

```
① 33 组扫描 → 选出 4 个敏感参数，但每组只跑了一次
        ↓ 问题：单次差值 0.0046，可能是噪声
③ 三 seed 复跑 → 确认提升是真的，但只用了一个结构
        ↓ 问题：换个结构还成立吗？
⑤ 结构对照 → 发现全局混合更好，但三者参数量不齐
        ↓ 问题：到底是结构赢，还是参数多赢？
⑥ 容量对齐 → 定性结论站得住，"ViT 最优"被推翻
        ↓ 问题：这个 0.99 可靠吗？
⑦ 对抗训练 → 不可靠，1.5% 扰动就崩；能修，但只护到 ε≈0.08
```

②（基准）和 ④（网格）是辅助：②给一把统一的尺子，④检查两个主参数有没有交互。

# 三、① S1 单因子扫描：33 组

## 在问什么

**11 个超参数，哪个动一下影响最大？**

不先问这个，后面就没法设计实验——你不知道该在哪个参数上花预算。

## 怎么做

固定其余一切，每次只改一个参数，跑一档看一次结果。11 个参数、32 个档位，加 1 次基准 = 33 次。

## 33 组的完整结果

| 参数 | 档位 | 验证集 AUC | 极差 |
| --- | --- | --- | --- |
| **lr** | 1e-4 / 3e-4 / 1e-3 / 3e-3 / 1e-2 | 0.9658 / 0.9761 / **0.9844** / **0.9879** / 0.9855 | **0.0220** |
| **optimizer** | SGD / Adam / AdamW | 0.9642 / **0.9844** / 0.9846 | **0.0204** |
| **use_bn** | True / False | **0.9844** / 0.9658 | **0.0186** |
| **conv_width** | 16 / 32 / 64 | 0.9790 / 0.9844 / **0.9890** | **0.0100** |
| pooling | light / none | **0.9844** / 0.9782 | 0.0062 |
| augment | none / flip / flip+rot | **0.9851** / 0.9844 / 0.9821 | 0.0030 |
| weight_decay | 0 / 1e-4 / 1e-3 | **0.9847** / 0.9844 / 0.9825 | 0.0022 |
| scheduler | none / step / cosine | **0.9844** / 0.9822 / 0.9822 | 0.0022 |
| batch_size | 32 / 64 / 128 | **0.9854** / 0.9844 / 0.9837 | 0.0017 |
| dropout | 0 / 0.2 / 0.4 | **0.9845** / 0.9844 / 0.9828 | 0.0016 |
| class_weight | none / balanced | 0.9844 / **0.9856** | 0.0012 |

（粗体是每一行最好的那档）

## 怎么读这张表

**看极差，不看最高值。** 极差 = 这个参数从最差档到最好档，能造成多大差异。

分成两组：

- **极差 > 0.01 的四个**：lr、optimizer、BN、conv_width。这四个值得调，也是后面 S2 的对象。
- **极差 < 0.003 的七个**：batch_size、weight_decay、dropout、augment、class_weight、scheduler、pooling。改它们的效果和种子波动一个量级，**调了等于没调**。

## 三个反直觉的发现（都会在第 15 页用到）

**1. 完全去掉池化反而更差**：pooling=none 是 0.9782，light 是 0.9844。
原因：池化不只是降维，还扩大了感受野。去掉之后每个神经元的视野更小，更看不到整片肺野。
→ 笔记 C3 里"池化会丢小结节"的说法，在这个任务上不成立。

**2. 增强越多越差**：none 0.9851 > flip 0.9844 > flip+rot 0.9821。
原因：加了 10° 旋转后，肺野被推出画布，四周补黑边——模型学到的是"黑边=异常"，而不是病灶。
→ 数据增强不是免费的，它改变了输入的分布。

**3. SGD 差了整整 2 个点**：0.9642 vs Adam 0.9844。
但这不能说"SGD 差"，只能说**在 20 轮预算内 SGD 没收敛**。给它 100 轮，差距可能消失。这是个很好的答辩点——区分"算法差"和"预算不够"。

## 这 33 组支撑了什么

- P5 的敏感性条形图（排序）
- P15 的第 Ⅰ、Ⅱ 条修正
- 决定了 S2 只在 lr 和 conv_width 上做网格

## 可能被问

**Q：为什么 lr 要试 5 档，别的只试 2–3 档？**
因为 lr 是唯一一个"差一个数量级就完全不能用"的参数（1e-4 欠拟合、1e-2 开始震荡），必须扫得密。其他参数在合理范围内变化平缓，2–3 档足够定位。

**Q：单因子扫描的缺陷是什么？**
看不到交互。比如 lr 单独最优不代表 lr 和 width 一起最优——这就是 S2 存在的理由。

**Q：33 组为什么不多跑几档？**
再细分的收益低于种子波动（实测 0.002–0.005），继续加密只是在测噪声。

# 四、② 基准配置：1 次

## 在问什么

**拿什么当"零"？**

## 怎么做

`conv_width=32, lr=1e-3, Adam, batch 64, 20 轮, 无增强`，跑一次得 0.984404。

## 为什么必须单独跑一次

因为后面所有"提升"都是相对它算的。如果基准值来自别的实验（比如 S1 里某一档），口径就不干净了——你不知道那个 0.9844 是在什么完整配置下得到的。

## 可能被问

**Q：基准为什么选这组配置，而不是随机初始化？**
因为这组是"教科书默认值"：Adam + 1e-3 + 中等宽度，没有针对任何指标调过。用一个"没被优化过"的起点，才测得出调参的真实收益。

# 五、③ S2 两两网格：4 组

## 在问什么

**lr 和 conv_width 是前两名敏感参数，它们会不会互相影响？**

## 怎么做

2×2 全组合：lr ∈ {1e-3, 3e-3} × width ∈ {32, 64}。

## 结果

| lr | width | AUC |
| --- | --- | --- |
| 1e-3 | 32 | 0.984404 |
| 1e-3 | 64 | 0.988956 |
| 3e-3 | 32 | 0.987870 |
| 3e-3 | 64 | **0.990669** |

## 关键：最优的那组为什么没被采用

`lr=3e-3 + width=64` 是 0.9907，比最终采用的 `lr=1e-3 + width=64`（0.9890）还高 0.0017。

**没有采用，因为它只有单次结果，没过 S3 的显著性检验。**

而 S3 复跑过 `lr=3e-3`（w32）：0.98787 / 0.98608 / 0.98743，均值 0.9871，标准差 0.00075。注意——S1 里它的单次值是 0.9879，复跑三次的均值掉到 0.9871。

这说明 **lr 单独调高带来的那点收益，在复跑之后会消失**。既然如此，`lr=3e-3 + w64` 的 0.9907 也很可能是单次运气，不能采信。

这条是整份工作纪律性的最好体现：**不因为某个配置单次更高就采用它，因为它没过自己定的判据。**

## 可能被问

**Q：既然 0.9907 更高，为什么不用？是嫌麻烦吗？**
不是。它是单次结果，没过三 seed 检验。同一套判据在 S3 里已经把 lr=3e-3 的单次优势证伪了（均值从 0.9879 掉到 0.9871），所以这个 0.9907 更像噪声。用了它就等于自毁判据。

**Q：那你不觉得可惜吗？**
不可惜。如果判据只在方便的时候遵守，它就不是判据。

# 六、④ S3 三随机种子：9 组

## 在问什么

**那个 +0.0046 的提升，是真的，还是这一次运气好？**

## 怎么做

三个配置 × 三个种子：
- `base`（w32, lr1e-3）
- `conv_width=64`（w64, lr1e-3）
- `lr=0.003`（w32, lr3e-3）

每个配置用 seed 0/1/2 各跑一次，**同种子配对相减**。

## 结果

| seed | base | w64 | 差值 | lr3e-3(w32) |
| --- | --- | --- | --- | --- |
| 0 | 0.984404 | 0.988956 | +0.004552 | 0.987870 |
| 1 | 0.984423 | 0.988080 | +0.003657 | 0.986080 |
| 2 | 0.984785 | 0.988898 | +0.004113 | 0.987432 |
| 均值 | 0.9845 ± 0.0002 | 0.9886 ± 0.0005 | **+0.0041** | 0.9871 ± 0.0008 |

## 为什么要配对，不能直接比均值

如果不配对：base 均值 0.9845、w64 均值 0.9886，差 0.0041。
看起来一样，但**配对能消掉"这个种子本身偏强"的影响**。比如 seed 2 两个配置都偏高（0.9848 / 0.9889），配对相减后这个偏差就被抵消了。

配对之后，三次差值 0.0046 / 0.0037 / 0.0041，**方向全部一致**——这才是"稳定提升"的证据。

## 三个判据（P9 的三个数字）

| 判据 | 值 | 含义 |
| --- | --- | --- |
| 幅度 | +0.0041 | 平均差值 |
| 相对波动 | 19× | 差值 ÷ base 标准差（0.000215）≈ 19 |
| 一致性 | 3/3 | 三个种子方向都为正 |

缺任何一项，就只能写成"敏感性观察"，不能写"提升"。

## 可能被问

**Q：只有 3 个种子，够吗？**
3 个是"能算标准差的最小数量"（n−1）。再多是 5 个、10 个，但对 0.004 量级的效应，3 个种子加上 19 倍效应量已经足够说明问题。工程上 79 次训练已经是预算上限。

**Q：19 倍这个数怎么来的？**
0.004107 ÷ 0.000215 = 19.1。分母是 base 三次结果的标准差（ddof=1），代表"同一配置重复跑的抖动"。差值是抖动的 19 倍，说明不是噪声。

# 七、⑤ 结构对照：6 组

## 在问什么

**MLP 和 ViT 谁更强？CNN 差多少？**

## 怎么做

同一个数据集、同一套优化设置（Adam 1e-3 / batch 64 / 20 轮 / 早停 5），各跑 3 个种子：
- MLP（100,738 参数）：3 次
- TinyViT（71,554 参数）：3 次
- CNN（74,946 参数）：**复用 repeats 里 w64 的 3 次**，不重复跑

## 为什么 CNN 不重跑

它的配置和 P9 的 w64 完全一样，重跑等于烧预算做同一件事。所以直接复用 `repeats.csv` 里那三行。这是"实验复用"，不是数据造假——答辩被问可以直说。

## 结果

| 结构 | 参数量 | 验证集 AUC | 标准差 |
| --- | --- | --- | --- |
| TinyViT | 71,554 | 0.9935 | 0.0006 |
| MLP | 100,738 | 0.9928 | 0.0009 |
| SmallCNN | 74,946 | 0.9886 | 0.0005 |

## 能说 / 不能说

- **能说**：全局混合（ViT、MLP）比局部卷积高 0.005–0.009，远超标准差。
- **不能说**：ViT > MLP。差 0.0007，而两者参数量差 3 万——这是**混淆变量**。

这就是 ⑥ 存在的理由。

## 可能被问

**Q：ViT 和 MLP 差 0.0007，你的标准差是 0.0009，是不是说明 ViT 更差？**
不能这么读。0.0007 远小于 0.0009，只能说"分不出高下"，不能说"MLP 更好"。统计上这叫"无显著差异"，不是"反向显著"。

**Q：为什么 MLP 参数最多却不如 ViT？**
因为参数量不是唯一变量。MLP 的全部参数都在第一层全连接上（784×128），参数效率低；ViT 的参数集中在注意力和 FFN 上，同样参数能表达更复杂的关系。这也说明"参数量"只是容量的粗略代理。

# 八、⑥ 容量对齐：18 组

## 在问什么

**把三个模型的参数量强行拉到同一水平，"结构更好"这个结论还成立吗？**

## 怎么做

两个容量档 × 三个结构 × 三个种子 = 18 次。

关键是"反解"：给定目标参数量（约 1.9 万 / 约 7.2 万），反推每个结构的宽度该设多少。

| 结构 | 调节的旋钮 | 1.9 万档实际值 | 7.2 万档实际值 |
| --- | --- | --- | --- |
| MLP | 隐藏层宽度 | width=24 → 18,890 | width=91 → 71,619 |
| SmallCNN | conv_width | 32 → 19,042 | 63 → 72,641 |
| TinyViT | dim | 32 → 19,394 | 64 → 71,554 |

（实际值不精确等于目标值，因为宽度只能取整数）

## 结果

| 容量档 | MLP | SmallCNN | TinyViT |
| --- | --- | --- | --- |
| ~1.9 万 | **0.9922** ±0.0009 | 0.9845 ±0.0002 | **0.9922** ±0.0015 |
| ~7.2 万 | 0.9927 ±0.0001 | 0.9879 ±0.0014 | **0.9935** ±0.0006 |

## 三条结论

**1. CNN 落后是结构性的。** 两档都低 0.005–0.008；7.2 万档它参数最多（72,641）、结果最差。**加参数补不回来。**

**2. "ViT 最优"站不住。** 1.9 万档 ViT 与 MLP 差 0.00008，7.2 万档差 0.00085——都在标准差之内。

**3. 容量在 1.9 万就饱和。** 1.9 万参数的 MLP（0.9922）和 7.2 万参数的 ViT（0.9935）只差 0.0013。加 3.8 倍参数换 0.0013，不值得。

## 修正后的说法

> 全局信息混合优于局部卷积；**注意力的额外贡献不显著**。

## 可能被问

**Q：怎么"反解"宽度的？**
给定目标参数量 P，先按结构写出参数量关于宽度的表达式（比如 CNN 近似二次函数），再二分搜索使实际参数量最接近 P。脚本里 `--dry-run` 只做这一步，不训练。

**Q：为什么是 1.9 万和 7.2 万两档，不是三档？**
1.9 万是 CNN 能压到的最小可用容量（再小性能塌），7.2 万是 ViT 的原始容量。两档已经能看出"容量增加有没有用"，第三档的边际信息很小。

**Q：既然容量饱和了，为什么最终还选 w64（7.5 万）？**
因为最终配置是为"精度最高"选的，不是为"参数最少"选的。如果目标是部署，应该选 w32 甚至更小——这也在 P16 的局限里说了。

# 九、⑦ 对抗训练：6 组

## 在问什么

**被 1.5% 的像素扰动打崩之后，训练时见过这种扰动，能不能救回来？代价多大？**

## 怎么做

同一网络、同一数据、同一预算，只改一件事：训练时每个 batch 混入 50% 的 FGSM 样本（ε=0.03）。

- 干净训练（对照组）：3 个种子
- 对抗训练：3 个种子

## 结果

| | 干净 AUC | ε=0.03 处 AUC |
| --- | --- | --- |
| 干净训练 | **0.9886** ±0.0005 | 0.4678 ±0.0554 |
| 对抗训练 | 0.9805 ±0.0028 | **0.8711** ±0.0130 |
| 差 | −0.0081 | **+0.4033** |

## 三个要点

**1. 代价很小，收益很大。** 干净精度掉 0.0081，鲁棒 AUC 涨 0.40。

**2. 崩溃被填掉了 79%。** 干净模型从 0.9886 掉到 0.4678（掉 0.52）；对抗模型从 0.9805 掉到 0.8711（掉 0.11）。0.11/0.52 ≈ 21%，即降幅收窄 79%。

**3. 保护只到 ε≈0.08。** ε≥0.2 两组都归零。因为训练时只见过 ε=0.03，超出这个邻域就没有约束。

## 一个必须主动承认的偏差

seed 0 和 seed 1 因为"用干净 AUC 早停"在第 12 轮就被截断（seed 2 跑满 20 轮、鲁棒性最好 0.886）。所以 **0.8711 是保守下界**，真实的对抗训练效果应该更好。

这不是甩锅，是说明"早停指标选错了"——早停应该看鲁棒指标，不是干净指标。这一条进了踩坑清单。

## 可能被问

**Q：为什么只做 FGSM，不做 PGD？**
FGSM 是单步，PGD 是迭代。单步训练便宜（和普通训练同一量级），先验证"这条路有没有用"。结果证明有用但范围有限，所以下一步才值得上 PGD。

**Q：0.008 换 0.40，值吗？**
看场景。筛查场景宁可牺牲 0.008 的干净精度，也不能被噪声骗过去——漏诊的代价远大于 0.008 AUC。

# 十、⑧ 正式训练：2 次

## 在做什么

用 S3 验证过的配置（w64, lr1e-3）训练最终权重，保存验证集 AUC 最高的那一轮（第 19 轮，0.9890），产出 `outputs/best.pth`。

## 为什么是 2 次

第一次产出权重；第二次是为验证可复现性重跑——**指标逐位一致（0.988956 / 0.95229）**。

这 2 次可以只讲成"1 次正式训练 + 1 次复现校验"，不必细说第二次是意外重跑。

## 可能被问

**Q：为什么保存第 19 轮而不是最后一轮？**
第 20 轮验证集 AUC 是 0.9837，第 19 轮是 0.9890。按"跑完取末轮"会白丢 0.0053。**早停 + 按验证集选轮**是标准做法。

# 十一、一张表：79 次 → 五个结论

| 结论（P16） | 来自哪几次 |
| --- | --- |
| 1. 调参带来稳定提升 +0.0041（19× std，3/3 同向） | S1（33）+ S3（9）+ base（1） |
| 2. 瓶颈不在超参数，1.9 万参数就饱和 | 容量对齐（18） |
| 3. 结构差异在信息混合的尺度，CNN 两档都低 | 结构对照（6）+ 容量对齐（18） |
| 4. 精度与鲁棒性是两个维度 | 对抗训练（6） |
| 5. 落差 89% 来自分布偏移 | test 评测（1 次，不计入 79 的训练） |

# 十二、评委可能怎么问"79"这个数字

**Q：79 次是怎么算的？**
六类：33 单因子 + 1 基准 + 4 网格 + 9 三 seed + 6 结构 + 18 容量 + 6 对抗 + 2 正式 = 79。

**Q：为什么不再多跑一些？**
单次训练 2–3 分钟，79 次约 4 小时纯算力，加上设计和排查是两周业余时间。再加密的边际收益低于种子波动。

**Q：79 次里有多少次是失败的？**
S1 里有 7 组明显异常（lr 两端、SGD、无 BN 等），全部保留在 CSV 里，没有删。**失败组也是证据**——它告诉你参数的可用边界在哪。

**Q：剪枝蒸馏那部分不算吗？**
不算在 79 里。那是另一批 7 次（剪枝 3 + 从头训 1 + 蒸馏 3），属于"网络压缩"的延伸实验，结果在 `compress.csv`。FGSM 的 9 档是评测，不训练。

**Q：如果重来，这 79 次会怎么分配？**
会把 S1 从 33 组压到 20 组左右（砍掉 7 个低敏感参数的多余档位），省下的预算做 PGD 对抗训练和阈值校准——后两者的信息量比把 batch_size 从 64 试到 128 更大。
