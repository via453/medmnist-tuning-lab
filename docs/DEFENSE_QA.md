# 答辩问答准备（建议稿）

> 5 分钟提问。以下答案基于 `results/*.csv` 与 `docs/FINAL_ANALYSIS.md` 的真实数据，用自己的话讲一遍；不确定的地方直接说「没做/不知道」，比硬答更稳。

## 高概率被问

**Q1. 导师建议的是医学图像分割或预测任务，你为什么做 28×28 分类？**
本项目落在「预测任务 + 基于基础预测模型调参」两条上。分割方向（U-Net + DRIVE）在纯 CPU、14 小时预算、中期就要交三件套的条件下风险过高：数据需注册、TIF/GIF 掩码格式坑多、训练慢。分类用官方标准化数据，能把精力放在调参实验设计与可复现链路上。选题论证见 `中期大作业选题建议.html`。

**Q2. 为什么用 val 调参、test 只评一次？**
`C1` 自测第三题写过「用训练集调参是看答案，换个新数据就不会了」。test 一旦参与选配置就失去独立性。`results/test_final.csv` 全程只有一行，且 `git_commit` 记录了评测时的代码版本。

**Q3. 提升只有 0.004，有意义吗？是不是噪声？**
S1 单 seed 时确实不能下结论，所以补了 S3：base `0.984537±0.000175`，`conv_width=64` `0.988645±0.000400`，差值 `+0.004107` ≈ base 标准差的 23 倍，明显大于两者波动。绝对幅度不大，要如实说「统计上稳定、绝对值有限」，不宣称刷点。

**Q4. val AUC 0.989，为什么 test 只有 0.955，ACC 从 0.952 掉到 0.835？**
MedMNIST 官方 INFO 说明：train/val 来自 source training set 的 9:1 划分，test 来自**独立的** source validation set，两者来源不同，存在分布差异（对应已学 `C11` 协变量偏移）。混淆矩阵里假阳性从 17 涨到 100，说明固定阈值 0.5 在 test 上偏高。**不能事后拿 test 调阈值**，那等于泄题；应把落差作为现象解释与后续工作。

**Q5. S2 网格里 `lr=0.003,conv_width=64` 的 val_auc 0.9907 更高，为什么不用？**
这是必须主动讲的一点：最终配置取自 S1 单因子最优并经 S3 验证，S2 的更优组合出现时 test 已经按纪律评过一次。为了更高分数回头改配置再评第二次，会破坏 test 的独立性。所以把该组合写成「遗留改进方向」，不返工。若导师要求补做，应在 `docs/LOG.md` 明确记录「重新定义最终配置并二次评测」及原因，并说明对结论可信度的影响。

**Q6. 为什么不用更大的网络 / 预训练 / ResNet？**
项目命题是「**同一个**基础预测模型靠调参提升」。换模型属于换假设空间，报告里单列为「结构对比」（L0/L1/L2），不算调参功劳。`conv_width` 从 32 到 64 已是容量维度的对照。

**Q7. 28×28 小图为什么还用池化？你笔记里不是说会丢小结节吗？**
`C3` 订正版指出的是**堆池化**会丢微小结节。本项目 `pooling=light` 只做一次 2×2 池化；S1 里 `pooling=none` 实测 0.9782，反而低于 `light` 的 0.9844。所以结论是「不堆、但保留一次下采样有帮助」，不是「完全不用池化」。

**Q8. 类别不平衡怎么处理？**
主指标用 AUC 而非 ACC。S1 里 `class_weight=balanced` 让 AUC 升到 0.9856，但 ACC 掉到 0.876，是典型的 AUC/ACC 分离，说明加权改变了决策边界。最终配置保留 `none`，并在报告里解释这个权衡。

**Q9. 数据合规吗？**
MedMNIST 为 CC BY 4.0，官方声明**仅用于教育与研究、不用于临床**。原始 `.npz` 在 `~/.medmnist/`，`data/` 已被 `.gitignore` 忽略，仓库只放脚本、配置与结果图；全篇不含诊断表述。

**Q10. 你的 TinyViT 为什么能赢 CNN？是不是注意力更先进？**
不是「更先进」，是「更匹配这个任务」。两者参数量几乎相同（71,554 vs 74,946），差别在信息混合方式：我的 SmallCNN 只池化一次，两层 3×3 卷积感受野只有 9×9，看不全 28×28；自注意力第一层就让任意两个 patch 直接相连。而本任务的证据是整片肺野的弥漫性浸润（全局统计），所以全局混合占优。若换成有 GPU、高分辨率、病灶是局部小块的场景，结论很可能反过来。
补一句限定：**ViT 赢的是 CNN，不是 MLP**。容量对齐后 ViT 与 MLP 打平（差 0.00008–0.00085，低于 seed std），见 Q15。

**Q11. 蒸馏为什么没用？是我做错了吗？**
不是做错，是前提不成立。师生差距只有 0.010（0.9890 vs 0.9791），软标签里几乎没有额外信息可传；而且只有 2 个类别，没有「类别间相似结构」可供蒸馏。三个温度 T=1/4/8 结果几乎一样，恰好说明 T 在这里不是有效旋钮。要看到蒸馏收益，需要更强的老师或更复杂的类别结构。

**Q12. AUC 0.989 是不是很好？**
看扰动条件。同一模型在 FGSM ε=0.03（约像素范围的 1.5%）时 AUC 掉到 0.45，ε≥0.05 直接退化成「全判正常」。所以准确率必须附带分布与扰动假设。这不是模型个例，是这类小数据医学影像模型的通病。

**Q13. val 掉到 test 差 0.117，是先验问题还是模型问题？**
拆过了：把 val 的阳性率对齐到 test 的 62.5%（200 次自助抽样），ACC 只从 0.9523 降到 0.9399±0.0036，即先验只解释 −0.0124（11%），剩下 −0.1050（89%）是真实分布偏移。所以「按 test 先验调阈值」最多挽回 1 个百分点，不能当解法。

**Q14. 既然 ε=0.03 就崩，那能修吗？修完还剩多少？**
能修一部分。训练时把一半样本换成 FGSM(ε=0.03) 对抗样本、与干净样本混在一起算损失（`configs/adv.yaml`），3 个 seed 配对对照：ε=0.03 处 AUC 从 0.4678 提到 **0.8711**（+0.40，崩溃被填掉 79%），代价是干净 AUC 从 0.9886 掉到 0.9805（−0.0081）、ACC −1.65 个点。三个 seed 方向全部一致。但保护是**局部**的：ε=0.08 时已掉到 0.46，ε≥0.2 两者都归零。所以这是「用 0.008 的干净精度换 0.40 的鲁棒 AUC」，不是免费午餐。

**Q15. 你上一轮说「ViT 最优」，这一轮又说不是，到底哪个对？**
后者对，前者是被参数量没对齐误导的。上一轮四组参数量是 19k–101k，不齐。这一轮我用脚本反解每个结构的容量旋钮，把三者压到 ~1.9 万和 ~7.2 万两档、各 3 seed 重跑：**CNN 的落后被证实且加参数救不回来**（两档都低 0.005–0.008），但 **ViT 与 MLP 的差距只有 0.00008（1.9 万档）与 0.00085（7.2 万档），落在 seed std 里**，甚至 1.9 万参数的 MLP 与 7.2 万参数的 ViT 只差 0.0013。所以正确说法是「全局信息混合 > 局部卷积，注意力的额外贡献不显著」。我把它当成这次项目最值钱的一条：**能推翻自己上一轮结论的实验，比多刷 0.002 AUC 有用。**

## 可能被追问的次要问题

- **环境踩过什么坑？** 裸装 `medmnist/scikit-learn` 经 scipy 把 numpy 顶到 2.x，导致 pandas / matplotlib / sklearn 因 C ABI 变化无法导入；已用 `requirements.txt` 钉死 numpy 1.x ABI 组合，`pip check` 无冲突。
- **剪枝 80% 为什么不如直接训个小模型？** 剪枝后剩 14,912 个非零参数，AUC 0.9720；从零训 w16 只有 4,914 参数却到 0.9791。单次 L1 剪枝 + 3 epoch 微调达不到彩票假说要求的「迭代剪枝 + 重训」，所以在这个规模上「剪大的」没有优势。
- **为什么保存最佳轮而不是最后一轮？** 训练第 20 轮 val_auc 0.9837 低于第 19 轮 0.9890；`run.py` 按 val_auc 保存最佳权重，`figures/metrics.json` 的 val AUC 与最佳轮一致，可核对。
- **怎么复现？** README 一键命令 + 固定 seed + `requirements.txt` + `git tag`；`runs.csv` 每行带 `git_commit`。
- **没做分割，会不会偏离方向？** 不回避：这是范围取舍，理由见 Q1；若后续有 GPU 与更多时间，可在同一套框架上补 U-Net 分支。

## 不要这样答

- 不要说「test 结果再调一下阈值会更好」——已评过一次，不能回头改。
- 不要说「提升达到 SOTA / 可用于临床辅助诊断」——数据集许可与小样本规模都不支持。
- 不要把 S2 更优组合说成「已经用上了」，或隐瞒它的存在；主动讲反而加分。
