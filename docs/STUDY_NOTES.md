> 这份文档不是讲稿，是**你自己把逻辑和数字吃透用的底稿**。  
> 目标：6 分半讲完，剩下 5 分钟答问。页面上只留结论，过程靠你讲。

# 一、先把主线记住

整个项目是一条「从相信到怀疑」的线。心里有这条线，16 页就不会散：

```
我做了个模型（P1-P3）
  ↓
先立规矩：数据怎么分、指标用什么、测试只评一次（P4-P5）
  ↓
问题一：调参有没有用？—— 有，但只有 0.0041（P9-P11）
  ↓
问题二：那什么更有用？—— 结构（P6-P7）
  ↓
但"结构谁最强"站得住吗？—— 站不住，容量没对齐（P8）← 全场最值钱
  ↓
问题三：0.99 这个分数可靠吗？—— 不可靠，1.5% 扰动就崩（P12-P14）
  ↓
所以我改了三处判断（P15），留下五条能复核的结论（P16）
```

**一句话版本**：我不是在证明"我的模型好"，我是在测量"它好在哪、什么时候会失灵、以及我之前的判断错在哪"。

# 二、页与页之间怎么接

这是整份讲稿最容易被忽略、也最容易讲散的地方。16 页不是 16 个并列的章节，是一条链：**每一页都在补上一页的缺口**。

| 衔接 | 上一页的落点 | 关系 | 下一页的起点 | 一句话过渡 |
| --- | --- | --- | --- | --- |
| 1→2 | 我提了三个问题 | 具体化 | 这三个问题花了多少工作量 | "这三个问题背后是 79 次训练，先说它怎么分配" |
| 2→3 | 五个阶段 | 并列（时间→空间） | 同一件事画成流程图 | "五个阶段按时间是串行的，画成图就是这四段" |
| 3→4 | 四段地图 | 进入第一段 | 数据与口径 | "从第一段开始：数据怎么分、指标用什么" |
| 4→5 | 数据口径定了 | 因果 | 还需要实验口径 | "数据定了，但还得定'凭什么说有效'，这就是实验设计" |
| 5→6 | 判定标准有了 | 必要前提（转折） | 要判断的对象是什么 | "判据只能判'谁更好'，还没说被判的是什么" |
| 6→7 | 理论假设：CNN 视野小 | 因果 | 用实验验证这个假设 | "如果'看不到全图'真是劣势，结果应该能看出来" |
| 7→8 | 结论有漏洞：参数量不齐 | 递进（补漏） | 补一组对齐实验 | "但这个结论有个洞——三者参数量差 3 万" |
| 8→9 | 结构这条线讲完了 | 回退（并列） | 回到最初的问题 | "结构说完了，回到最开始那个问题：调参本身有没有用" |
| 9→10 | 三个判据给了结论 | 递进（给证据） | 把原始数字摆出来 | "判据是结论，支撑它的原始数字在这" |
| 10→11 | 三 seed 确认方向 | 因果 | 落到可复现的配置 | "验证过了，就该落到最终配置" |
| 11→12 | 配置确定了 | 转折 | 它凭什么判断 | "配置定了，但它在看哪里？万一看的是黑边呢" |
| 12→13 | 注意力落在肺野 | 递进 | 换一家医院的片子 | "在自己数据上没作弊，换一家医院呢" |
| 13→14 | 换域掉 11 个点 | 递进（更极端） | 人为加噪声 | "自然偏移掉 11 点，那有人故意干扰呢" |
| 14→15 | 很脆弱，但能修 | 因果 | 三处判断被推翻 | "一路下来，有三处判断被推翻了" |
| 15→16 | 三处修正 | 收束 | 最后留下什么 | "改完判断，最后留下什么" |

**用法**：讲完一页时，不要直接翻页，先说表格右列那句话，再翻。一句话就能把两页焊住。

**名词**

| 术语          | 定义                 | 在本项目的体现              |

## 第 4 页 · 任务、数据与三个硬约束

**【承上】**：上页给出了路线图，第一段是数据

**这页为什么在**：先定口径。不先说清"用什么指标、怎么分数据"，后面所有数字都能被质疑。

**页面上每个数字**

| 元素     | 值         | 从哪来 / 怎么算                 |
| ------ | --------- | ------------------------- |
| 图像规格   | 28×28 单通道 | MedMNIST v2 统一规格          |
| 总量     | 5,856     | 4,708 + 524 + 624         |
| 验证集阳性率 | 74.2%     | 389 / 524（混淆矩阵 8+381=389） |
| 测试集阳性率 | 62.5%     | 390 / 624（混淆矩阵 3+387=390） |
| 主指标    | AUC       | 见下                        |

**名词深挖**

| 术语           | 一句话                      | 严格定义                                      | 本项目的值                                           |
| ------------ | ------------------------ | ----------------------------------------- | ----------------------------------------------- |
| **AUC**      | 随机取一个正例一个负例，模型把正例排前面的概率  | ROC 曲线下面积，等价于 Wilcoxon 秩和统计量归一化；**与阈值无关** | val 0.9890 / test 0.9546                        |
| **ACC**      | 判对的比例                    | (TP+TN)/N                                 | val 0.9523 / test 0.8349                        |
| **F1**       | 精确率与召回率的调和平均             | 2PR/(P+R)                                 | val 0.9682 / test 0.8826                        |
| **混淆矩阵**     | 四格：判对正常 / 误报 / 漏诊 / 判对肺炎 | TN / FP / FN / TP                         | val [[118,17],[8,381]]；test [[134,100],[3,387]] |
| **阳性率 / 先验** | 样本里病人占多少                 | P(y=1)，prevalence                         | 74.2% → 62.5%                                   |
| **阈值**       | 判定的分数线                   | 概率 ≥ 0.5 判肺炎                              | 全程固定 0.5                                        |

**为什么主指标是 AUC 而不是 ACC**

1. **ACC 会被类别比例骗**：测试集 62.5% 是肺炎，全判肺炎就有 62.5% ACC——一个什么都没学的模型。
2. **ACC 依赖阈值**：0.5 是人为选的，换阈值 ACC 就变，AUC 不变。
3. **AUC 衡量排序能力**：临床上更关心"病人排在健康人前面"，这正是 AUC 的定义。

代价也要说：AUC 高不代表概率校准好。所以 P13 特意报了固定阈值 0.5 下的 ACC，让读者看到"排序能力强，但阈值换一家医院就不合适"。

**三个硬约束**

| 约束        | 具体做法                    | 违反的后果                    |
| --------- | ----------------------- | ------------------------ |
| 不重切数据     | 用官方 train/val/test      | 换一套划分，数字无法与公开结果比较        |
| 验证集只做选择   | 所有调参只看 val              | 一旦用 test 选型，test 就不再是留出集 |
| test 只评一次 | `test_final.csv` 只有 1 行 | 多次评测等于用 test 调参          |

**为什么选这套数据**

- 优点：CPU 十分钟一轮，4.7k 张能支撑 30 组以上对照。
- 代价：val 与 test 来源不同（这个代价在 P13 变成主角）。

**对应笔记**：C1（指标与模型选择）、C11（先验/类别比例的影响）。

**脱稿只说这几句**

> 任务是 28×28 胸片二分类，主指标用 AUC 而不是准确率——因为 AUC 与阈值无关，也不受病人比例影响。数据用官方划分。这里埋个伏笔：两边阳性率从 74.2% 掉到 62.5%，第 13 页会算它造成多少落差。

**可能被问**

- **Q：为什么不用 F1 作主指标？** F1 也依赖阈值。AUC 是阈值无关的，更适合"先看模型有没有判别能力"这个阶段。
- **Q：524 张验证集够吗？** 不够大，所以一个种子不可信——这正是 P10 做三 seed 的原因。524 张下 ACC 的标准误约 1%，0.004 级别的差异必须靠配对 + 多种子才能分辨。

## 第 5 页 · 实验设计 33 / 4 / 9 / 1

**【承上】**：有了数据口径，还需要判定标准

**这页为什么在**：整份工作的方法论核心。它回答"凭什么相信你那个 0.0041"。

**页面上每个数字**

| 数字 | 含义        | 具体内容                                 |
| -- | --------- | ------------------------------------ |
| 33 | S1 单因子    | 11 个超参数 × 1–5 档，含 1 次基准              |
| 4  | S2 网格     | lr {1e-3, 3e-3} × width {32, 64} 全组合 |
| 9  | S3 三 seed | 3 个配置（base / w64 / lr3e-3）× 3 个种子    |
| 1  | test      | 只报告，不回头改                             |

**33 组的分布**（背下来）

```
lr           5 档  1e-4 / 3e-4 / 1e-3 / 3e-3 / 1e-2
optimizer    3 档  SGD / Adam / AdamW
batch_size   3 档  32 / 64 / 128
weight_decay 3 档  0 / 1e-4 / 1e-3
dropout      3 档  0 / 0.2 / 0.4
use_bn       2 档  True / False
augment      3 档  none / flip / flip+rot
class_weight 2 档  none / balanced
scheduler    3 档  none / step / cosine
conv_width   3 档  16 / 32 / 64
pooling      2 档  light / none
```

**名词深挖**

| 术语           | 定义                          | 在本项目的具体表现                                         |
| ------------ | --------------------------- | ------------------------------------------------- |
| **单因子扫描的局限** | 看不到参数间的交互效应                 | lr 单独最优 ≠ lr+width 组合最优 → S2 的理由                  |
| **配对比较**     | 同一条件下两组相减                   | 同 seed 下 w64 − base，消掉种子本身的强弱                     |
| **种子标准化**    | random / numpy / torch 三处全设 | 13 次等价 base 复现到小数点后六位                             |
| **早停**       | 验证指标连续 5 轮不升就停              | patience=5，上限 20 轮                                |
| **组内极差**     | 同一参数各档的最大值 − 最小值            | lr 0.0220、optimizer 0.0204、BN 0.0186、width 0.0100 |
| **判定标准**     | 什么条件下才允许写"提升"               | 差值 > 数倍 std，且三种子同向                                |

**这页最关键的一层逻辑**

33 组单因子只能**排序**，不能**下结论**：单次差值 0.0046 小于组内极差 0.0220——这个差在噪声里。所以才有 S3。

这条讲不清，后面所有"提升"都站不住。这是整场最容易被追问的方法论。

**为什么只对 lr 和 width 做网格**：S1 显示这两个是前两名敏感参数（0.0220 / 0.0100），交互最可能出现在它们之间。三个以上参数全网格是组合爆炸。

**7 个异常组**：lr=1e-4（欠拟合）、lr=1e-2（震荡）、SGD（20 轮没收敛）、无 BN、pooling=none、flip+rot（旋转破坏肺野）、dropout=0.4。全部保留。

**对应笔记**：C1（实验设计）、C2（优化技巧——33 组里 lr/optimizer/BN/scheduler 的极差就是 C2 的实测数字）。

**脱稿只说这几句**

> 33 组单因子只能排序，不能下结论——单次差 0.0046，而组内极差有 0.0220。所以要 9 组配对复跑，最后才进测试集。这一页是整份工作的判定标准。

**可能被问**

- **Q：为什么不做全网格？** 11 个参数每档 2–5 个取值，全组合是 10⁵ 量级。单因子 + 两两网格是预算内最有效的采样。
- **Q：13 次复现到六位小数是什么意思？** 同一配置同一种子重复跑 13 次，结果完全一致（0.984404），说明随机性被完全控制。
- **Q：早停 patience 为什么是 5？** 20 轮预算下，5 轮不升基本可确认进入平台；太小会误杀，太大浪费预算。

## 第 6 页 · 三种结构

**【承上】**：实验设计定了比较规则，这页说被比较的三个东西是什么

**这页为什么在**：唯一一页纯理论页。它讲清"三个模型差在哪"，P7、P8 的结论才有落脚点。

**核心一句话**：三个模型唯一被改变的变量是**信息在什么尺度上被混合**。

**页面上每个数字（参数量怎么来的）**

| 模型            | 参数量     | 逐层计算                                                         |
| ------------- | ------- | ------------------------------------------------------------ |
| MLP           | 100,738 | 784×128 + 128 + 128×2 + 2                                    |
| SmallCNN w32  | 19,042  | conv1 288 + BN 64 + conv2 18,432 + BN 128 + FC 130           |
| SmallCNN w64  | 74,946  | conv1 576 + BN 128 + conv2 73,728 + BN 256 + FC 258          |
| TinyViT dim64 | 71,554  | patch_embed 1,088 + cls 64 + pos 3,200 + 2 层编码器约 66.9k + 分类头 |

（CNN 第二层通道是宽度的 2 倍：w32 → 32→64，w64 → 64→128）

**名词深挖**

| 术语            | 一句话               | 严格定义                   | 本项目的值                    |
| ------------- | ----------------- | ---------------------- | ------------------------ |
| **感受野**       | 一个神经元"能看到"原图多大一块  | 输出某点所依赖的输入区域           | **实测 7×7**               |
| **卷积核 3×3**   | 3×3 小窗在图上滑动       | 每处加权求和，权重共享            | 两层都是 3×3、padding=1       |
| **padding=1** | 四周补一圈 0           | 保持输出尺寸不变               | 28→28                    |
| **BN**        | 每层输出先标准化再缩放       | `γ(x−μ)/σ+β`           | 去掉掉 1.9 点（0.9844→0.9658） |
| **池化**        | 2×2 取最大压成一个数      | 降分辨率、扩感受野、减参数          | 只做一次（light）              |
| **GAP**       | 整张特征图取平均          | global average pooling | 14×14×64 → 64            |
| **patch**     | 把图切成小块当"词"        | 28÷4=7，共 49 块          | patch=4                  |
| **cls token** | 额外加的可学习"汇总位"      | 与 patch 一起进注意力，最后用它分类  | 1 个，dim=64               |
| **自注意力**      | 每个位置问所有位置"你和我有关吗" | `softmax(QKᵀ/√d)·V`    | 4 头                      |
| **pre-norm**  | 先归一化再进子层          | `x + Attn(LN(x))`      | 2 层                      |
| **FFN**       | 注意力后的两层全连接        | dim→2dim→dim           | 64→128→64                |
| **O(n²)**     | 49 个 token 两两算    | 复杂度随 token 数平方         | 训练 2.4 vs 1.2 min        |

**感受野到底多大（必须能自己推）**

结构是 `conv3×3 → pool2×2 → conv3×3`：

- 第一层 conv：每个输出点看 3×3 → **RF = 3**
- 池化 2×2 stride 2：步长放大到 2 → RF = 3 + (2−1)×1 = **4**
- 第二层 conv 3×3，步长累计 2 → RF = 4 + (3−1)×2 = **8**

**但实测是 7×7**：把输入设为可求导，对第二层 conv 的中心输出反传，梯度非零的输入范围是 11–17 共 7 像素。差 1 像素来自 padding=1 与偶数 kernel 的对齐。

页面上写 **7×7**。7×7 = 49，占 784 的 **6.2%**——不到十二分之一。

**为什么这个数字重要**：本任务的判别证据是「整片肺野的弥漫性浸润」，属于全局统计量。7×7 看不到整片肺野，这是理论上 CNN 处于劣势的原因，也是 P7 实验的假设来源。

**对应笔记**：C3（卷积、参数量手算、池化）、C4（自注意力）、C5（Transformer）。

**脱稿只说这几句**

> 三个模型唯一的差别是信息在多大的范围里被混合。MLP 第一层就能混合全图；CNN 两层叠起来只看得到 7×7，不到全图的 6%；ViT 每个 patch 都能直接问其他 patch。而这个任务的证据是整片肺野的浸润——所以"能不能看到全图"可能比"看得多细"更重要。

**可能被问**

- **Q：7×7 怎么算的？** conv 3、池化后 4、第二层 conv 加 (3−1)×2=4，合计 8；实测梯度回传是 7，差 1 来自 padding 对齐。两者都远小于 28。
- **Q：为什么不用更深的网络扩大感受野？** 20 轮预算内加深会显著拖慢收敛；加池化能扩感受野但会丢细节——这条在 P15 第 Ⅰ 条被实验否定了一半。
- **Q：ViT 训练为什么贵？** 49 个 token 两两算注意力，O(n²)；CNN 是局部卷积 O(n·k²)。实测 2.4 vs 1.2 min。

---

**【启下】**：如果'看不到全图'真是劣势，实验结果应该能看出来。

## 第 8 页 · 参数量对齐（重点①）

**【承上】**：上页的结论下不了，因为参数量没对齐

**这页为什么在**：全场最能体现科研素养的一页——**用新实验推翻自己上一轮的结论**。

**页面上每个数字**

| 容量档 | MLP | SmallCNN | TinyViT |
| --- | --- | --- | --- |
| 目标 ~1.9 万 | width=24 → 18,890 | conv_width=32 → 19,042 | dim=32 → 19,394 |
| 目标 ~7.2 万 | width=91 → 71,619 | conv_width=63 → 72,641 | dim=64 → 71,554 |

| 容量档 | MLP AUC | CNN AUC | ViT AUC |
| --- | --- | --- | --- |

**名词深挖**

| 术语 | 定义 | 在本项目 |
| --- | --- | --- |
| **参数量** | 可训练参数个数 | `sum(p.numel() for p in model.parameters())` |
| **容量** | 模型能装多少信息 | 用参数量近似；不完美但可比 |
| **容量对齐** | 把不同结构的参数量调到同一水平 | 只有结构变、容量不变 |
| **反解** | 给定目标参数量反推超参数 | 二分搜索宽度/dim |

**反解具体怎么做**：写出参数量关于宽度的表达式（CNN 近似二次、MLP 线性）→ 在合理区间二分搜索使实际值最接近目标 → 只实例化不训练（`--dry-run`），几秒得到结果。

**三条结论，措辞要精确**

1. **CNN 落后是结构性的**：两档都低 0.005–0.008；7.2 万档参数最多（72,641）却最差 → "加参数无法弥补"。
2. **"ViT 最优"站不住**：1.9 万档差 0.00008，7.2 万档差 0.00085，都在 std 内。
3. **容量在 1.9 万就饱和**：1.9 万 MLP（0.9922）vs 7.2 万 ViT（0.9935），只差 0.0013。

**修正后的表述**：全局信息混合 > 局部卷积；**注意力的额外贡献不显著**。

**对应笔记**：C3（参数量手算——能手算才敢反解）、C1（控制变量）。

**脱稿只说这几句**

## 第 9 页 · 调参 +0.0041

**【承上】**：结构线讲完，回到调参本身

**这页为什么在**：回答"调参有没有用"。答案是"有用，但小"——而"小"必须用判据撑住，否则就是个笑话。

**页面上每个数字**

| 数字 | 值 | 怎么算的 |
| --- | --- | --- |
| 平均差值 | +0.0041 | (0.004552 + 0.003657 + 0.004113) / 3 = 0.004107 |
| 相对波动 | 19× | 0.004107 ÷ 0.000215（base 三次的样本标准差）= 19.1 |

**名词深挖**

| 术语 | 定义 | 在本项目 |
| --- | --- | --- |

## 第 12 页 · 可解释性 Grad-CAM

**【承上】**：上页给了最终模型

**这页为什么在**：防守。证明模型看的是病灶，不是黑边、体位标记这类"捷径特征"。如果它能靠边框判断，前面所有精度都不可信。

**Grad-CAM 具体六步**

1. 前向传播，取最后一层卷积的输出（14×14×64）；
2. 对目标类的得分反向传播，得到特征图每个通道的梯度；
3. 每个通道的梯度做全局平均，得到"这个通道有多重要"的权重；
4. 特征图按权重加权求和，再 ReLU（只保留正贡献）；
5. 双线性上采样到 28×28，与原图对齐；
6. 归一化后以热力图叠加显示。

**页面上每个数字**

| 数字 | 值 | 怎么算的 |
| --- | --- | --- |
| 边框响应占比 | 0.382 | 8 个样本热图落在边框环内的比例均值 |
| 边框面积占比 | 0.490 | 28×28 去掉中间 20×20，剩 384 像素，384/784 = 49.0% |
| 富集倍数 | 0.78× | 0.382 ÷ 0.490 |

**名词深挖**

| 术语 | 定义 | 在本项目 |
| --- | --- | --- |
| **Grad-CAM** | 用梯度给特征图通道加权，得到"哪里重要" | hook 实现，不改模型代码 |
| **hook** | PyTorch 的前向/反向钩子 | 取出最后一层 conv 的激活与梯度 |
| **上采样** | 把小图放大 | 14×14 → 28×28 |
| **富集倍数** | 响应占比 ÷ 面积占比 | =1 均匀，>1 偏向该区域 |

**为什么 0.382 不能单独看**：边框面积占 49%，完全随机的模型在边框里也会有 49% 的响应。所以必须比"相对于面积"的倍数。0.78 < 1，说明注意力偏中央——反过来说，如果只报 0.382，听起来像"很依赖边缘"。

**对应笔记**：C10（可解释性）。

**脱稿只说这几句**
> 热图落在肺野，不在四边。定量上边框响应 0.382、面积 0.490，比值 0.78，小于 1，说明注意力偏中央。这个指标必须和面积一起报，否则 0.382 会被误读。

**可能被问**
- **Q：Grad-CAM 能证明模型真的在推理吗？** 不能证明因果，只能说明注意力落点。它能排除"靠边框作弊"这类捷径，但不能保证学到的是医学特征。
- **Q：为什么只有 8 个样本？** 定性展示用 8 个；定量统计用的是同一批样本的均值。要更强证据需要全量 524 张的分区统计，留作后续。

**【承上】**：上页证明注意力落在肺野

**这页为什么在**：全场最诚实的一页。它承认模型在真实数据上掉 11 个点，并把落差拆开，说明哪部分是数据的问题、哪部分是模型的问题。

**页面上每个数字**

**两张混淆矩阵的完整解读**

| | 判为正常 | 判为肺炎 | 合计 |
| --- | --- | --- | --- |

**这个对比很关键**：模型不是"变笨了"，而是**变得过于敏感**——把大量健康人判成肺炎。这正是先验下降（病人比例从 74% 降到 62.5%）时固定阈值的典型表现。

**拆解的三行**

| 场景 | ACC | 怎么来的 |
| --- | --- | --- |
| val 全量（阳性 74.2%） | 0.9523 | 原始验证集 |
| 只把先验对齐到 62.5% | 0.9399 ±0.0036 | 从 val 里按 62.5% 阳性率有放回重采样 200 次 |
| 真实 test（阳性 62.5%） | 0.8349 | 官方测试集 |

**名词深挖**

| 术语 | 人话 | 严格定义 | 在本项目 |
| --- | --- | --- | --- |
| **分布偏移** | 换了一家医院 | P(x) 不同 | 设备、体位、人群构成不同 |
| **先验 / 类别比例** | 病人占多少 | P(y) | 74.2% → 62.5% |
| **协变量偏移** | 输入样子变了，标签规则没变 | P(x) 变、P(y\|x) 不变 | 属于分布偏移的一种 |

| **阈值失配** | 阈值在 74.2% 上定的，搬到 62.5% 不合适 | 固定 0.5 不变 | 误报率 12.6% → 42.7% |

**11% / 89% 怎么算的**

- 总落差：0.9523 − 0.8349 = 0.1174
- 先验能解释：0.9523 − 0.9399 = 0.0124 → **10.6%**
- 剩下：0.9399 − 0.8349 = 0.1050 → **89.4%**

**为什么"调阈值不是解法"**：把阈值调低，误报减少但漏诊增加，总误差只是换个位置。所以只能承认这是分布问题，不是调参能解决的。

**图表说明**：ROC 和混淆矩阵都是**验证集**的。测试集只有一行数字，为守住"只评一次"没有重复出图。

**对应笔记**：C11（领域自适应）、C1（测试集只评一次）。

**脱稿只说这几句**

## 第 14 页 · 对抗训练（重点③）

**【承上】**：上页说换域会掉 11 个点

**这页为什么在**：回答"0.99 可靠吗"。答案是"不可靠"，并给出一个可量化的修补方案和代价。

**页面上每个数字**

| 数字 | 值 | 怎么算的 |
| --- | --- | --- |
| 0.47 → 0.87 | ε=0.03 处 AUC | 干净训练 0.4678；对抗训练 0.8711 |
| −0.0081 | 干净 AUC 代价 | 0.9886 − 0.9805 |
| 79% | 降幅收窄比例 | (0.9886−0.4678=0.5208) vs (0.9805−0.8711=0.1094)；1 − 0.1094/0.5208 = 79% |
| ε≈0.08 | 保护上界 | ε=0.08 时仍 +0.416；ε≥0.2 两组归零 |

**名词深挖**

| 术语 | 人话 | 严格定义 | 在本项目 |
| --- | --- | --- | --- |
| **FGSM** | 朝"让它判错"的方向推一小步 | `x' = x + ε·sign(∇ₓL)`，只走一步 | ε=0.03 |
| **ε** | 推多大 | L∞ 扰动半径，每个像素最多改 ε | 0.03 相对 [-1,1] 约 1.5% |
| **对抗样本** | 人眼看不出、模型判错的图 | 加微小扰动后预测翻转 | AUC 从 0.99 掉到 0.47 |
| **对抗训练** | 训练时混入对抗样本 | 每个 batch 取 50% 样本做 FGSM 再算损失 | ratio=0.5 |
| **鲁棒性** | 抗干扰能力 | 扰动下指标下降的幅度 | 干净 0.5208 vs 对抗 0.1094 |
| **单步 / 迭代** | FGSM 一步，PGD 多步 | PGD 更强 | 本项目只做单步 |

**为什么保护只在 ε≈0.08 以内**：训练时只见过 ε=0.03 的扰动，模型学到的是这个邻域的形状。超出邻域就没有约束了。这是单步训练的通病，也是下一步换 PGD 的原因。

**一个必须主动承认的偏差**：seed 0 和 seed 1 因为"用干净 AUC 早停"在第 12 轮被截断（seed 2 跑满 20 轮、鲁棒性最好 0.886）。所以 **0.8711 是保守下界**。

这不是甩锅，是说明"早停指标选错了"——早停应该看鲁棒指标，不是干净指标。这一条进了踩坑清单。

**对应笔记**：C9（对抗攻击）。

**脱稿只说这几句**
> 推到 ε=0.03，也就是 1.5% 的像素变化，干净模型的 AUC 从 0.9886 掉到 0.47，基本是反着判。对抗训练把同一点拉回 0.87，代价是干净精度掉 0.0081。但保护只到 ε 约 0.08，再大两组都崩——所以更严格的做法是迭代式的 PGD。这页想说一句话：99% 准确率必须附带扰动假设。

**可能被问**
- **Q：为什么只做 FGSM，不做 PGD？** 单步训练便宜（和普通训练同量级），先验证这条路有没有用。结果证明有用但范围有限，下一步才值得上 PGD。
- **Q：0.008 换 0.40，值吗？** 看场景。筛查场景宁可牺牲 0.008 的干净精度，也不能被噪声骗过去——漏诊代价远大于 0.008 AUC。
- **Q：为什么 ε=0.03 就崩这么厉害？** 28×28 只有 784 个像素，每个改 3% 已经能改变局部纹理；而模型没有做过任何鲁棒性正则。

# 六、五分钟问答准备

### 关于结构

**Q：ViT 到底赢没赢？**
赢了 CNN，和 MLP 打平。差 0.0007 在种子波动内。真正起作用的是"全局混合"，不是注意力本身。

**Q：为什么你的 CNN 这么弱？是不是没调好？**
两档参数量都试过，7.2 万档它参数最多结果最差。原因是感受野 7×7 覆盖不到全图 6%，而任务是弥漫性浸润——结构不匹配，不是没调好。（若换成局部病灶如结节，结论可能反过来。）

**Q：为什么不用 ResNet / 预训练模型？**
28×28 灰度图，ResNet 的下采样会把 28 压到 7 甚至 1，结构不匹配；预训练权重是 224×224 自然图像，迁移收益有限。

### 关于调参

**Q：+0.0041 有意义吗？**
单独没有。有意义的是它大于种子波动的 19 倍且 3 个种子同向。这个判据可以迁移到任何调参实验。

**Q：为什么不做网格搜索全覆盖？**
11 个参数全组合是 10⁵ 量级，CPU 上不可能。单因子 + 两两组合是预算内最有效的采样。

**Q：为什么不做交叉验证？**
为了和官方划分对齐；而且"测试只评一次"这条纪律下，交叉验证的"验证"就变成测试了。验证集 524 张确实少，所以用三个种子补。

### 关于评测

**Q：验证集 0.95、测试集 0.83，是不是过拟合？**
不是。过拟合表现为训练高验证低；这里是验证高测试低，属于分布偏移。先验只解释 11%，89% 是设备/体位/人群差异。

**Q：为什么不调阈值让测试集好看一点？**
调阈值只是把误报换成漏诊，总误差不变。而且那等于用测试集做决策，违反纪律。

### 关于鲁棒性

**Q：对抗训练值不值？**
看场景。筛查场景宁可牺牲 0.008 的干净精度，也不能被 1.5% 的噪声骗过去。但当前只护到 ε≈0.08，需要换 PGD。

**Q：为什么 ε=0.03 就崩了？**
784 个像素、每个改 3%，已经能改变局部纹理；模型没有做过任何鲁棒性正则。

### 可能的追问

**Q：这个项目最弱的一环是什么？**
对抗训练用干净 AUC 早停，seed 0/1 在第 12 轮被截断，所以 0.8711 是保守下界。

**Q：如果重做一遍，先改哪一步？**
先固定"早停指标 = 最终目标"，再碰模型。

**Q：你和别人的工作比，增量在哪？**
不是精度。是把"调参收益 vs 结构收益"用同一套预算、同一套判据量了出来，并且公开了一个被自己推翻的结论。

# 八、附录：6 分半连续版

把上面的关键句连起来，就是一段可以完整练的串词。约 1,450 字，正常语速 6 分半。
**练的时候不要背字，记每段的第一句和最后一个数字。**

> 各位老师好，我是 Zelvia。汇报题目是 MedMNIST 医学影像分类调参实验室。
> 一句话概括：我用胸片二分类这个任务跑了 79 次训练，回答三个问题——调参有没有用、结构是不是更重要、一个 0.99 的模型有多脆弱。
>
> 先说规模。79 次分五个阶段：划分数据、写三种结构、单因子扫描 33 组、三 seed 复跑 9 组、最后测试一次。最关键的一条纪律：79 次里只有 1 次碰测试集，其余 78 次都在 524 张验证集上完成。
>
> 这一页是全场的地图，四段加一条回路。蓝色虚线是调参回路，只走验证集——这就是为什么测试结果全程只出现一次。
>
> 任务很直接：28×28 灰度胸片，判断正常还是肺炎。主指标用 AUC 而不是准确率，因为 AUC 与阈值无关，也不受病人比例影响。这里埋个伏笔：验证集阳性率 74.2%，测试集 62.5%，第 13 页我会算它造成多少落差。
>
> 设计是 33、4、9、1。33 组单因子只能排序，不能下结论——单次差 0.0046，而组内极差有 0.0220，这个差淹没在噪声里。所以要 9 组配对复跑，最后才进测试集。这一页是整份工作的判定标准。
>
> 接下来是三种结构。它们唯一的差别，是信息在多大的范围里被混合。MLP 把图展平，第一层就能混合全图；CNN 两层 3×3 叠起来只看得到 7×7，不到全图的 6%；ViT 把图切成 49 块，每块都能直接问其他块。而这个任务的证据是整片肺野的浸润，属于全局统计量——所以"能不能看到全图"可能比"看得多细"更重要。
>
> 结果是 ViT 0.9935、MLP 0.9928、CNN 0.9886。能说的只有一句：全局混合比局部卷积好 0.005 到 0.009。但 ViT 和 MLP 只差 0.0007，参数量却差了 3 万，所以"ViT 最优"这个结论我不能下。
>
> 所以下一页我去把它证伪。我按真实参数量反解每个结构的宽度，压到 1.9 万和 7.2 万两档再比。结果两条：第一，CNN 落后是真的，两档都低 0.005 到 0.008，而且 7.2 万档它参数最多、结果最差——加参数补不回来；第二，"ViT 最优"站不住，差只有万分之几，落在种子波动里。更关键的是，1.9 万参数的 MLP 和 7.2 万参数的 ViT 只差 0.0013，说明容量在 1.9 万就饱和了。
>
> 回到调参。固定结构，只把宽度从 32 改到 64，三次配对：平均 +0.0041，是标准差的 19 倍，三个种子全部同向。三个判据都满足，才敢写"提升"。但这个提升只在 CNN 内部有效。
>
> 最终配置只有六行，全来自验证过的结论，删掉的比留下的多。权重取第 19 轮而不是最后一轮——第 20 轮反而掉了 0.0053。
>
> 有人会问：这个模型是靠看病灶，还是靠看黑边？热图显示注意力落在肺野。定量上，边框响应占 0.382，而边框面积本身就占 0.490，比值 0.78，小于 1，说明注意力偏中央。这个指标必须和面积一起报，否则 0.382 会被误读。
>
> 测试集只评一次：AUC 0.9546，准确率 0.8349，比验证集掉 0.1174，假阳性从 17 涨到 100。落差从哪来？我把验证集阳性率对齐到 62.5% 重采样 200 次，准确率只掉到 0.9399——先验只解释 11%，剩下 89% 是真实的分布偏移：设备、体位、人群都不一样。调阈值不是解法，只是把误差挪个位置。图上这两张是验证集的，测试集只有一行数字。
>
> 那这个 0.99 可靠吗？推到 ε=0.03，也就是 1.5% 的像素变化，干净模型的 AUC 从 0.9886 掉到 0.47，基本是反着判。对抗训练把同一点拉回 0.87，代价是干净精度掉 0.0081。但保护只到 ε 约 0.08，再大两组都崩——所以更严格的做法是迭代式的 PGD。这一页想说一句话：99% 准确率必须附带扰动假设。
>
> 有三处判断被实验推翻了：完全去掉池化反而更差；加旋转增强反而更差，因为把肺野推出了画布；ViT 最优在容量对齐后站不住。三处都改成了带条件的表述——结论范围变窄了，但每一条都能用结果表复核。
>
> 收口。五条结论：调参有效但小；瓶颈不在超参数而在结构；结构差异是信息混合的尺度；精度和鲁棒性是两回事；落差主要来自分布。两条局限我先说清楚：只做分类、单数据集、20 轮预算。一条纪律：测试只评一次，所以更好的配置我也没采纳。
>
> 我的汇报到这里，谢谢。
